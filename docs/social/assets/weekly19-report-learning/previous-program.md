## Frozen contract

Test whether the report-informed guide can be made shorter without losing its evidence and editorial constraints. This is a documentation-concision experiment. It does not measure model behaviour, readership, conversion, or reach. The report corpus supplies the rules; autoresearch-rs selects a concise expression of those rules. Manual review checks meaning beyond the literal anchors.

Reuse the already authorised isolated experiment repository at `content/experiments/2026-11-01-post-refinement/repository`, with no remote. A new committed baseline and run branch remain inside that repository. Keep the earlier run and its evidence intact. The marketer repository's history remains outside this experiment.

The only mutable path is `learning/guide.md`. Freeze the evaluator, required clauses, source report metrics, and this plan before baseline. The objective is total words, minimised. Hard gates require all protected clauses, the three operational sections, a substantive guide, and no unsupported performance promise. The baseline is the first full report-informed draft, saved as `content/experiments/2026-11-02-report-learning/guide-baseline.md`.

Evaluate one shortened candidate and one negative control that removes the explicit prohibition on invented experience and unsupported numbers. Maximum two candidates. The negative control must fail its hard gate even if shorter. Verify the retained commit with the frozen evaluator, save the report and stop the run.

## Cases covered by the contract

| Case | Required treatment |
|---|---|
| Account and scheduler totals differ | Preserve both scopes; inspect definitions rather than silently reconcile |
| The same audience value is labelled people and times | Mark ambiguous; do not call it unique reach |
| A metric is absent | Unavailable rather than zero |
| A best-day summary conflicts with weekday advice | Preserve the authorised calendar |
| A historical reach outlier carries unverified model claims | Verify claims before reuse; reach cannot waive evidence |
| A suggested hook invents a client incident | Reject; use verified experience or labelled hypothetical |
| A weak post has a useful technical test | Bring the action forward while retaining the mechanism |
| Advice suggests dropping qualifications | Preserve essential caveats, versions and sources |
| A template requires a metric or contrarian story | Do not manufacture either |
| A question adds no useful response opportunity | End with an action instead |
| LinkedIn-only observations are available | Do not infer an X result |
| A concise guide passes offline checks | No claim of measured reach or behavioural improvement |

These are human-reviewed scenarios represented by protected instruction clauses, not executed model cases. There is no held-out model evaluation in this run. Word-count improvement is meaningful only as reduced instruction length with the reviewed meaning retained.
